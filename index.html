기능무엇이고, 왜 쓰나
프로젝트 같은 주제의 대화와 자료를 한곳에 묶는 폴더입니다. 관련 자료를 한 번만 올려두면 그 프로젝트 안의 모든 대화가 그걸 참고합니다.
예: "2026 신제품 출시" 프로젝트를 만들고 기획서 · 경쟁사 자료 · 가격표를 올려두면, 그 안에서 물어볼 때마다 배경을 다시 설명하지 않아도 됩니다. 회의록, 고객 응대, 특정 제품처럼 계속 돌아오는 주제라면 무조건 만드는 게 낫습니다.
아티팩트 문서나 표, 웹페이지처럼 결과물이 대화 옆 별도 창으로 열리는 것입니다. 대화에 섞여 스크롤로 사라지지 않습니다.
거기서 바로 "이 문단 줄여줘"처럼 고쳐달라고 할 수 있고, 공유 링크로 만들어 팀에 보낼 수도 있습니다. 긴 문서나 자료를 만들 때 "아티팩트로 만들어줘"라고 하면 그 형태로 나옵니다.
연동 내가 쓰는 서비스를 연결해두면 파일을 매번 올리지 않아도 됩니다. Google Workspace(Gmail · 드라이브 · 문서), Microsoft 365(Outlook · Teams), GitHub가 기본 제공됩니다.
연결하면 "내 드라이브에서 지난달 보고서 찾아서 요약해줘"처럼 부탁할 수 있습니다. 회사 계정이면 관리자가 어떤 연동을 허용할지 정합니다 — 목록에 없으면 IT에 문의하세요.

한국어 공식 문서에 "프로젝트란 무엇인가요?", "아티팩트란 무엇이며 어떻게 사용하나요?", "커넥터를 사용하여 Claude의 기능 확장하기" 라는 제목으로 자세한 안내가 있습니다. 교육 탭의 링크에서 찾으실 수 있습니다.

Chat을 한 단계 더 청소년

기본 요령이 손에 붙었다면, 이 네 가지가 결과물의 급을 올립니다.

요령어떻게
예시로 톤 맞추기잘 쓴 우리 문서 하나를 올리고 "이 톤과 형식 그대로". 형용사 열 개보다 예시 하나가 정확합니다.
한 개 말고 세 개 받기"서로 다른 방향으로 3안"을 시키면 고르고 섞을 수 있습니다. 첫 안을 붙잡고 고치는 것보다 좋은 결과가 빨리 나옵니다.
일부러 반박시키기초안이 나오면 "이 계획의 허점을 셋만 찾아줘". Claude는 내 말에 맞춰주는 경향이 있어서, 반대 입장을 시켜야 빈틈이 보입니다.

Cowork — 맡기는 요령 청소년

Chat과 가장 다른 점은 내가 지켜보지 않아도 된다는 것입니다. 대신 맡길 때 정해줘야 할 것이 있습니다.

  1. 먼저 정하세요 — 내 파일이 필요한 일인가.
    필요 없으면 클라우드에서 돌리세요. 컴퓨터를 꺼도 계속 진행되고 다른 기기에서 이어볼 수 있습니다.
    내 파일을 다뤄야 하면 데스크톱 앱을 열어 둔 상태로 돌려야 합니다.
  2. 맡겨놓고 앱을 닫지 마세요. 가장 흔한 실수입니다. 내 파일을 다루는 작업은 앱이 열려 있는 동안만 진행됩니다. 닫으면 멈춥니다.
  3. 작업 폴더는 좁게 주세요. 시작할 때 어느 폴더에서 작업할지 묻습니다. 홈 폴더째 열어주지 말고 필요한 폴더만 지정하는 게 안전합니다.
  4. 무엇이 완성인지 적어주세요. 되물을 사람이 없으니 "결과를 어떤 형태로 어디에 남길지"까지 써야 합니다. "정리해줘"가 아니라 "표로 만들어서 이 폴더에 엑셀로 저장해줘".
  5. 처음 며칠은 결과를 직접 확인하세요. 목록에 초록색으로 끝났다고 표시되어도 일이 제대로 됐다는 뜻은 아닙니다. 실행을 열어 내용을 봐야 합니다.
Cowork 쓰기 전 두 가지 설정

데이터 폴더를 Documents 밖으로 옮기세요. 기본 위치가 Documents 아래여서, 클라우드 동기화 폴더와 겹치면 문제가 생깁니다. 설정 → Cowork files에서 바꿉니다.

용량을 씁니다. Cowork는 별도 공간에서 돌아가서 디스크를 적잖이 씁니다. 부족해지면 Cowork 디스크 공간 확보 기능이 있고, 작업 결과물은 지우지 않고 임시 파일만 정리합니다.

Code — 코드를 몰라도 만들 수 있습니다 청소년

개발자만 쓰는 곳이 아닙니다. 코드를 한 줄도 못 읽어도, 원하는 걸 말로 설명하면 만들어 줍니다. 핵심은 결과를 눈으로 확인하면서 고쳐나갈 수 있다는 것입니다.

비개발자에게 이게 왜 되나

만든 화면을 바로 띄워서 보여줍니다. 웹페이지를 만들면 Claude가 알아서 서버를 띄우고 앱 안의 브라우저 창에 열어줍니다. 코드를 볼 필요 없이 결과 화면을 보고 "이 버튼 색 바꿔줘"라고 하면 됩니다. 확인까지 스스로 합니다 — 아래 검증 항목에.

이런 걸 만듭니다

실제로 비개발자가 많이 만드는 것들입니다.

만드는 것예
한 장짜리 웹페이지행사 안내, 제품 소개, 사내 공지 페이지. 지금 보고 계신 이 문서도 이렇게 만든 것입니다.
자료를 보여주는 화면엑셀 데이터를 표와 차트가 있는 페이지로. 매번 엑셀을 열어 보여주는 것보다 편합니다.
간단한 사내 도구계산기, 견적 산출, 체크리스트, 신청 양식처럼 반복 작업을 대신하는 작은 도구.
문서 · 매뉴얼 사이트여러 페이지를 모아 검색되는 형태로. 팀에 공유하기 좋습니다.
자료 정리 자동화파일 이름 바꾸기, 여러 파일 합치기, 형식 변환처럼 손으로 하면 오래 걸리는 정리 작업.

처음 시작하는 법

준비물은 빈 폴더 하나입니다.

  1. 빈 폴더를 만드세요. 이름은 아무거나 — 예: 행사안내페이지. 여기에 결과물이 쌓입니다.
  2. Code 탭에서 그 폴더를 엽니다. 처음 열 때 이 폴더에서 작업해도 되냐고 물으니 허용해주세요.
  3. 원하는 걸 말로 설명하세요. 코드 이야기는 할 필요 없습니다.
    예: "10월 신제품 발표회 안내 페이지를 만들어줘. 일정과 장소, 신청 버튼이 있고, 휴대폰에서도 잘 보여야 해."
  4. 화면이 떠오르면 보고 말하세요. "제목이 너무 크다", "신청 버튼을 위로", "회사 색인 남색으로". 코드가 아니라 보이는 것을 말하면 됩니다.
  5. 참고할 이미지를 주면 훨씬 정확합니다. 마음에 드는 다른 사이트 스크린샷을 붙이고 "이런 느낌으로"라고 하세요.
직원처럼 쓴다는 것

성인 단계의 관점은 하나입니다 — Claude를 기능이 아니라 직원처럼 다루는 것. 업무 지시서를 쓰고(스킬), 정기 업무를 배정하고(예약 작업), 출입 범위를 정하고(폴더 · 권한), 결과를 검수합니다(검증).

그리고 직원과 다른 점 하나 — 한 일이 전부 시킨 사람 이름으로 남습니다. 팀에 붙이기 전에 책임부터 정하세요.

컨텍스트를 관리하며 오래 가기 청소년

긴 작업에서 품질이 떨어지는 원인은 대개 컨텍스트가 찬 것입니다. 눈에 안 보여서 원인을 엉뚱한 데서 찾게 됩니다.

상황대처
차면 자동으로 요약됩니다 Code 탭은 컨텍스트가 차면 대화를 스스로 요약하고 계속 진행합니다. 멈추지는 않지만 앞부분의 세부가 흐려집니다 — 초반에 정한 규칙이 뒤에서 지켜지지 않으면 이걸 의심하세요.
원하는 시점에 압축하기 /compact를 쓰면 내가 고른 시점에 요약합니다. 한 단계를 끝낸 직후처럼 버릴 게 명확한 지점에서 하는 게 좋습니다.
지금 얼마나 찼는지 보기 모델 선택기 옆의 사용량 링을 누르면 컨텍스트 사용량과 플랜 사용량이 보입니다. 컨텍스트는 세션별이고, 플랜 사용량은 모든 표면이 공유합니다 — 다른 창에서 쓴 것도 함께 차오릅니다.
대화에 싣지 말 것 매번 붙여넣는 지식은 프로젝트로, 반복하는 절차는 스킬로 빼세요. 대화가 가벼워지면 긴 작업이 훨씬 안정적입니다.

여러 작업을 동시에 굴리기 청소년

하나 시켜놓고 기다리는 게 가장 큰 낭비입니다. Code 탭은 병렬을 전제로 설계돼 있습니다. 창을 다루는 키는 단축키 탭에.

방법내용
세션을 여러 개 열기 git 저장소라면 각 세션이 프로젝트의 격리된 사본에서 작업합니다. 그래서 한 세션의 변경이 다른 세션에 영향을 주지 않습니다 — 같은 파일을 건드리는 작업도 동시에 굴릴 수 있습니다.
자리를 떠야 할 때 오래 걸리는 작업은 클라우드로 넘기면 컴퓨터를 꺼도 진행됩니다. 다른 기기에서 이어받을 수도 있습니다.
끝나면 알림이 옵니다 보고 있지 않은 세션이 작업을 마치면 OS 알림이 옵니다. 그래서 여러 개를 굴려도 놓치지 않습니다.

Cowork의 경계를 설계하기 성인

Cowork를 오래 쓰면 "무엇을 할 수 있나"보다 "어디까지 닿게 둘 것인가"가 문제가 됩니다.

경계설계 기준
로컬 · 클라우드 분리는 보안 경계다 클라우드 세션은 의도적으로 로컬 자원에 닿지 못합니다. 편의가 아니라 격리입니다 — 내 파일이 필요한 작업을 클라우드로 넘기려는 시도는 방향이 틀렸습니다. 작업을 쪼개서 로컬이 필요한 부분만 데스크톱에 남기세요.
앱이 닫히면 끊기는 것 로컬 파일 접근 · 브라우저 자동화 · 컴퓨터 사용 · 라이브 아티팩트는 앱이 열려 있는 동안만 동작합니다. 긴 작업을 설계할 때 이 네 가지가 필요한 구간을 미리 갈라두면 중간에 멈추는 일이 없습니다.
예약 세션은 다른 스킬을 씁니다 예약된 Cowork 세션은 내 컴퓨터의 스킬 폴더를 읽지 않습니다. 계정에 켜 둔 스킬을 세션 시작 시 동기화해서 씁니다 — 로컬에서만 되던 자동화가 예약으로 돌리면 실패하는 이유가 이것입니다.
디스크는 계속 늘어납니다 가상 머신 기반이라 세션이 쌓입니다. 정리 기능은 실행 중이 아닌 세션의 캐시와 임시 파일만 지우고 작업 공간의 결과물은 건드리지 않습니다 — 안심하고 돌려도 됩니다. 데이터 폴더는 동기화 폴더 밖으로 옮겨두세요.

Claude가 스스로 검증하게 두기 청소년

직접 눌러보고 확인하는 시간이 가장 아깝습니다. Code 탭은 자기가 만든 걸 자기가 확인하도록 설계돼 있습니다.

동작내용
고칠 때마다 자동 확인 기본 설정에서 수정 직후 스스로 검증합니다. 서버를 띄워 화면을 열고 스크린샷을 찍고, 요소를 살피고, 버튼을 누르고, 입력창을 채워보며 찾은 문제를 고칩니다. 프런트엔드뿐 아니라 백엔드도 — API를 호출하고 서버 로그를 읽습니다.
권한 확인 없이 돕니다 내 로컬 개발 서버와 프로젝트 파일은 승인이 필요 없어서 자동 검증이 끊기지 않습니다. 반면 외부 사이트에 작용할 때는 안전 검사가 붙고, Auto·Bypass 외의 모드에서는 도메인 허용 확인까지 거칩니다.
우리 프로젝트 방식에 맞추기 서버 실행 명령이 특이하면 .claude/launch.json을 프로젝트 방식에 맞게 고치면 됩니다. 그러면 매번 설명하지 않아도 알아서 띄웁니다.
로그인 상태는 분리돼 있습니다 앱 안 브라우저는 내 개인 브라우저와 분리된 깨끗한 프로필입니다 — 저장된 로그인이 없습니다. 내 계정으로 동작해야 하는 일이라면 이 창이 아니라 Chrome 확장을 써야 합니다.

실패 모드 도감 성인

오래 쓰면 도구의 실패 패턴이 곧 내 작업의 한계가 됩니다. 이름으로 알아두면 증상이 보이는 순간 대처가 나옵니다.

설치가 막히면 IT 담당자에게 "Git for Windows 설치"라고 요청하시면 됩니다.

스킬이 뭔가요

같은 지시를 반복해서 붙여넣고 있다면 그게 스킬로 만들 후보입니다. 그 지시를 한 번 저장해두면, 관련된 일을 부탁할 때 알아서 꺼내 쓰거나 이름으로 직접 불러올 수 있습니다.

예를 들어 "우리 회사 보도자료 형식", "고객 문의 답변 톤", "주간 보고 양식" 같은 것들. 매번 설명하지 않아도 됩니다.

어렵지 않습니다. 지시문을 적은 파일 하나를 압축해서 올리면 끝입니다.

  1. 폴더를 하나 만들고 이름을 정합니다. 예: 보도자료-형식
  2. 그 안에 SKILL.md라는 이름의 텍스트 파일을 만듭니다. 파일 이름은 정확히 이래야 합니다.
  3. 맨 위에 이름과 설명을, 아래에 지시 내용을 씁니다. 아래 예시를 그대로 복사해 고쳐 쓰세요.
  4. 폴더를 ZIP으로 압축합니다.
  5. Customize → Skills → + → Upload a skill에서 ZIP을 올립니다. 목록에 나타나면 켜고 끌 수 있습니다.

잘 쓰는 요령 청소년

스킬이 안 먹히는 이유는 거의 설명과 길이 두 가지입니다.

증상원인과 해결
써야 할 때 안 쓴다 설명에 내가 실제로 입에 올릴 단어가 없어서입니다. 기능 이름이 아니라 부탁할 때 쓸 표현을 넣으세요 — "보도자료", "프레스 릴리스", "언론 배포용"처럼 여러 가지로.
확인하는 법 — Claude에게 "사용 가능한 스킬이 뭐야?"라고 물어보면 목록이 나옵니다.
안 써야 할 때 쓴다 설명이 너무 넓습니다. 더 좁고 구체적으로 고치세요.
가끔 무시된다 스킬이 많아지면 설명이 잘려서 판단 근거가 사라집니다. 핵심 용도를 설명 맨 앞에 쓰세요 — 뒤쪽이 먼저 잘려 나갑니다.
이상하게 느려진다 지시 내용을 짧게 쓰세요. 스킬은 한 번 불려오면 이후 대화에도 계속 남아 있어서, 긴 내용은 계속 부담이 됩니다. 왜 그런지 설명하지 말고 무엇을 할지만 적으세요.
두 종류로 나눠 생각하면 쉽습니다

형식 · 규칙형 — 문서 양식, 말투, 우리 회사 용어. Claude가 알아서 참고하게 두면 됩니다. 설명을 잘 쓰는 게 전부입니다.

절차형 — 순서가 정해진 작업. 이건 내가 부를 때만 돌아야 하니, 이름으로 직접 불러 쓰세요.

무엇을 스킬로 만들지 청소년

스킬을 만들기 시작하면 아무거나 만들게 됩니다. 만들 가치가 있는지 먼저 걸러야 관리가 됩니다.

판단기준
만들 만하다세 번 이상 같은 지시를 붙여넣었다. 그리고 그 지시가 거의 안 바뀐다. 회사 문서 양식, 응대 톤, 검토 기준처럼요.
아직 아니다매번 조건이 달라지는 일. 스킬로 굳히면 맞지 않는 상황에도 끌려갑니다. 이럴 땐 프로젝트에 참고 자료로 두는 편이 낫습니다.
스킬 대신 프로젝트필요한 게 지시가 아니라 자료라면 프로젝트에 올리세요. "이 자료를 참고해라"는 스킬로 만들 게 아닙니다.
스킬 대신 예약 작업지시가 아니라 시점이 문제라면 자동화입니다. "매주 월요일"이 핵심이면 스킬이 아니라 예약 작업입니다.

팀에 공유하기 성인

  1. 올린 스킬은 기본적으로 나만 씁니다. 공유하려면 회사 계정(Team · Enterprise)이어야 합니다.
  2. 소유자가 조직 설정 → Skills에서 공유를 켜야 구성원이 공유할 수 있습니다.
  3. 켜지면 특정 사람 · 그룹 · 조직 전체로 범위를 골라 공유합니다.
  4. 받은 사람은 내용을 고칠 수 없습니다. 켜서 쓰기만 가능합니다 — 그래서 수정 요청이 모일 관리자 한 사람을 정해두는 게 좋습니다.

Code 탭에서도 쓰려면 성인

Code 탭과 앱은 스킬을 다른 데서 읽습니다

Chat과 Cowork는 위에서 올린 계정에 등록된 스킬을 씁니다. Code 탭은 내 컴퓨터의 ~/.claude/skills/ 폴더에 있는 파일을 읽습니다. 같은 계정이어도 서로 안 보입니다.

그리고 규격이 다릅니다. Code 탭용으로 만든 스킬을 앱에 올리면 오류로 실패합니다 — 앱 업로드는 맨 위 항목을 여섯 개(name, description, license, compatibility, metadata, allowed-tools)만 허용합니다.

둘 다 쓸 스킬이라면 맨 위 항목을 name과 description 둘만 두세요. 그 형태는 양쪽 모두에서 동작합니다.

팀에 도입하는 순서 성인

자료만 뿌리면 아무도 안 씁니다. 순서가 중요합니다.

  1. 경계부터 정합니다. 어떤 자료까지 올려도 되는지(반출 기준), Cowork에 어느 폴더까지 열어줄지. 개인이 즉석에서 판단할 문제가 아닙니다.
  2. 공용 자동화는 책임자를 정하고 시작합니다. 예약 작업이 한 일은 전부 돌리는 사람 이름으로 남습니다 — 업무 자동화 탭의 주의 그대로입니다.
  3. 공유 스킬은 관리자를 둡니다. 받은 사람이 고칠 수 없으니, 수정 요청이 모일 한 사람이 필요합니다.
  4. 배포는 이 페이지와 한국어 공식 문서를 함께. 영어 강좌부터 보내면 이수율이 낮습니다. Mac · Windows 차이(퀵 엔트리는 Mac만, Cowork는 Windows에서 조건)도 먼저 공지하세요.
  5. 직무별로 실제 업무 하나를 같이 해봅니다. 전체에 다 뿌리면 안 봅니다 — 강좌보다 우리 일로 한 번 성공하는 경험이 훨씬 강합니다.
  6. 팀에서 통한 요청문은 스킬로 굳혀 공유합니다. 성공이 개인기로 남지 않게.
